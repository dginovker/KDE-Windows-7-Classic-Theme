# Windows 7 Classic for KDE Wayland

Build an independently maintained Classic UI with a live return to the user's current desktop. This is research and planning, not an installable theme.

- `PROJECT-DIRECTION.md`: confirmed goals, proposed boundaries and first milestone.
- `reference/gallery.html`: genuine Windows 7 beside the earlier A/B experiments; click images for original pixels.
- `reference/README.md`: measurements, VM provenance and unresolved risks.
- Check the gallery: `python reference/verify.py` (requires Pillow).
- `vm/`: test VMs. `vm/vmctl.py lab start`, then `sh`/`user` (stdin script as root / as the `tester` desktop user), `put`/`get`, `click x y`, `type`, `key`, `shot`. Input never touches the host desktop. `vm/prepare-tester.sh` (run via `vm/vmctl.py lab sh`) recreates `tester` for a pristine stock Plasma 6.8.2 session.

No host theme, session or boot changes are authorized by these artifacts. Preserve unsaved work; Linux authentication and reliable apply/restore remain unverified. Work is tracked in GitHub issues.

## Install and toggle

Arch: `cd packaging && makepkg -si` (uses Wine's LGPL Tahoma and `python-fonttools`; tested with Plasma/KWin 6.8.2 and Qt 6.12). Before removing the package, run `win7-classic current`; removal warns about anyone still in Windows mode. For development, first install the package: the Win7Classic Qt style must be system-wide so already-running apps can discover it. Then `./install.sh` updates the user-local surfaces (requires the same build dependencies). Both install and Windows-mode activation refuse a missing system style (fix: `cd packaging && makepkg -si`). Nothing changes on screen until you switch.

`win7-classic windows|current|toggle|status|restore` swaps the whole Plasma panel/desktop layout and panel theme by restarting only plasmashell; KWin and applications keep running. Each mode keeps its own saved layout under `~/.local/state/win7-classic/`, and every switch is logged there. Colors, fonts, widget style and window decoration are swapped key-by-key (only the keys listed in `toggle/windows/keys/`), so other settings in `kdeglobals`/`kwinrc` stay untouched, and running Qt apps update live. A switch that fails (e.g. a widget plugin is missing) rolls back and stays in the old mode; `restore` brings back the current layout from a terminal even with no panel running. The first switch builds Windows mode from your current panel (`toggle/windows/seed`): the launcher, task manager, clock, show-desktop and spacers become the Classic ones; every other widget (pager, monitors, your own widgets, the tray and its items) keeps its settings; unrelated widgets sit before the notification area. `win7-classic rebuild` discards the Windows layout and builds it again from the current one.

## Firefox and Dark Reader

Firefox's **System theme — auto** follows the GTK/desktop light preference live; no Firefox profile writes or restart are needed for normal mode switches. An explicitly selected Firefox Dark/custom theme remains the user's choice, not a per-mode preference managed by this project.

If History has black text on a nearly black background while the toolbar is light, check custom `chrome/userChrome.css`. A blanket `browser { background-color: #131314 !important; }` also overrides Firefox's privileged History sidebar. Scope that blank-page workaround to content tabs instead:

```css
#tabbrowser-tabpanels browser { background-color: #131314 !important; }
```

Keep unrelated CSS unchanged. Back up the file before editing; Firefox reads userChrome.css at startup, so this repair takes effect on the next normal Firefox restart. It is not a live stylesheet migration performed by `win7-classic`. The History defect was reproduced without Dark Reader installed.

Dark Reader is separate: **Automation → Use system color scheme**, with behavior **Toggle on/off**, follows the existing live light/dark signal when Firefox follows the system. This is opt-in configuration in Dark Reader; the switcher does not change automation, enabled state, site lists or other extension settings. A manually enabled Dark Reader can still darken web content in Windows mode. Disabling the extension alone can leave injected styles on running pages, so it is not a reliable live substitute. Missing/disabled extensions require no integration. Automatic control of arbitrary Dark Reader settings, with exact per-mode restoration, is not implemented.

## Desktop Recycle Bin

A new Windows profile seeds Plasma’s **Trash** widget on a clear primary desktop. Its empty and full icons come from Windows 7; Plasma keeps its own caption and status text. Click it to open the real `trash:/` in Dolphin, with KDE’s Restore and Empty Trash actions and normal confirmation policy. Other folders still open in Explorer.

The seed never creates a Desktop file. It leaves existing Trash widgets and populated or customized Folder View desktops alone so it cannot duplicate a Trash link or cover an owner’s icons. Already saved Windows layouts are not reseeded. To opt in on such a layout, switch to Windows mode, open **Add Widgets**, and place **Trash** in a free spot if you don't already have a Trash entry. Switch back to current mode to save that placement in the Windows profile only. No rebuild is needed.

## Optional Classic desktop menu

The system package adds **Windows 7 Classic Desktop Menu** to Plasma's Mouse Actions list. Installing it does not change any binding. To use it only in Windows mode:

1. Run `win7-classic windows`. On empty desktop space, open **Desktop and Wallpaper** from the existing menu. With the stock binding you can also use **Ctrl+Shift+D** while the desktop has focus.
2. Open **Mouse Actions**. Note the current **Right-Button** action (normally **Standard Menu**) and record any settings you rely on using that row’s settings button. Change only that row to **Windows 7 Classic Desktop Menu**, then click **OK**. Leave any other mouse actions and widgets as they are.
3. Right-click empty desktop space to check the menu. Run `win7-classic current` to save the edited Windows profile and return to your unchanged current-mode bindings. The menu will be there on the next `win7-classic windows`.

**Before uninstalling:** enter Windows mode again, right-click empty desktop space and choose **Personalize → Mouse Actions**. Set **Right-Button** back to the action you noted in step 2. Plasma can reset an action’s options when you change its type; use that row’s settings button to restore the options you noted, then click **OK**. Check that the original menu returns, then run `win7-classic current` to save that reversal to the Windows profile before removing the package. If you separately selected the Classic menu in current mode or on another trigger, undo each of those selections in the mode where you made it. No rebuild or profile reset is needed.

The Classic menu uses real Plasma Folder View and KIO actions for View, Sort by, Refresh, New and Paste. New lists Folder and Shortcut first. Shortcut opens KDE’s symlink dialog; KDE templates and URL/application links remain available. Paste shortcut creates a filesystem link for local file URLs. Screen resolution, Gadgets and Personalize open the KDE settings or widget browser; More icon options, Undo and Edit Mode keep KDE's functionality. Icon and file commands require Folder View. Independent grid snapping and show/hide all desktop icons or gadgets are not provided. Normal file, widget and panel menus are unchanged.

## Optional Windows taskbar appearance

In Windows mode, right-click an empty part of the **Windows 7 Classic taskbar** widget and choose **Configure Windows 7 Classic taskbar → Appearance**. **Use a plain folder icon for the closed Explorer pin** only changes that pin's artwork to the Windows 7 folder. The pinned app, its running location icon and its jump list are unchanged. Uncheck it to restore the native Explorer launcher artwork.

For a shorter taskbar, use Plasma's **Show Panel Configuration → Panel height** on the Windows panel. The default remains 44 logical px. The Classic controls fit a shorter panel, but Plasma can squeeze other widgets below their minimum heights; it does not guarantee that they still fit. At 150%, 36 logical px (54 physical px) was the smallest tested with a two-row pager, stock System Tray and monitor, and widgets requiring 32 logical px inside the panel. Try 38 (57 physical px) for more room. A 30-logical-pixel panel (45 physical px) leaves only 26 px for those widgets and is not suitable for that layout. Raise the height again if any control becomes hard to see or use.

A normal `win7-classic current` saves both Windows-only adjustments; the next `win7-classic windows` restores them. No `rebuild` is needed. To undo, uncheck the icon option and set the Windows panel back to its previous height.

## Mixed installs and removal

A package plus a development install must both be upgraded: `cd packaging && makepkg -si`, then `./install.sh` as the desktop user. Each cleans its own legacy renderers; install/switch warnings identify legacy copies in the other root. Only the known old Classic decoration identity is migrated in live/saved current settings.

Saved Windows layouts from older releases can still contain a separate Quick Launch toolbar. On the next activation of a saved Windows layout, its main/popup URLs are folded into that panel's existing Classic pins (existing pin order first, Dolphin mapped to Explorer, duplicates removed). Only the migrated widget and its order entry are removed; other widgets, nested tray configuration and current mode are not reseeded. A panel without a Classic taskbar is left alone; ambiguous destinations or missing explicit saved Classic pins fail and roll back. A read-only migration plan is validated before a complete original Windows profile recovery copy is created; only then can the layout be changed. The recovery copy is retained under `~/.local/state/win7-classic/profiles/windows-before-quicklaunch.*` and its path is logged. When upgrading while already in Windows mode, a normal `current` → `windows` round trip captures the latest live pin edits and applies this migration; `rebuild` is not needed. Installation itself does not migrate or restart the running panel.

Before removing the package, run `win7-classic current`. If current mode itself uses Classic, first select a different current decoration. Package removal warns about user-local renderers and leaves them untouched. Remove those exact project renderers explicitly (configs and saved profiles stay):

```
rm -rf "${XDG_DATA_HOME:-$HOME/.local/share}"/kwin/decorations/win7classic{,2} "${XDG_DATA_HOME:-$HOME/.local/share}"/win7-classic/primitives{,2}
```

## Lock and login screens

Windows mode locks with a Windows 7 logon-style screen (`plasma/lockscreen/`, `plasma/logon/`); current mode keeps Plasma's. Plasma reads the lock screen from its shell package, so Windows mode adds `~/.local/share/plasma/shells/org.kde.plasma.desktop/` (marked by `.win7-classic`): links to the system shell, plus real copies of `lockscreen/` (ours) and `logout/`. If the Windows lock screen fails to load, a plain password field replaces it. If you can't unlock, run `loginctl unlock-sessions` from a TTY.

The package also installs the SDDM theme `win7-classic`. SDDM is system-wide, so it is not toggled; to select it:

```
printf '[Theme]\nCurrent=win7-classic\n[General]\nInputMethod=qtvirtualkeyboard\n' | sudo tee /etc/sddm.conf.d/win7-classic.conf
```

The supported X11 greeter configuration is the drop-in above plus the `qt6-virtualkeyboard` dependency. The Ease of Access button is intentionally hidden when the virtual keyboard is unavailable. Replace any old `Current`-only drop-in with the command above. Qt Virtual Keyboard is an Arch package dependency; installation and mode switching do not change SDDM settings. Delete the drop-in to return to your previous login screen and input method. A KWin Wayland greeter uses its own compositor keyboard instead. If the theme fails to load, SDDM shows its built-in one.

Both Classic surfaces use Windows 7 Ultimate's genuine 16:10 logon bitmap, account surround, branding and submit button. At 100%, the bottom-left Ease of Access art and the SDDM split power control come from the genuine Windows captures. The Ease of Access button shows or hides the existing virtual keyboard, not the Windows Ease of Access suite. It appears only at a password prompt with an available backend: Plasma's configured KWin virtual keyboard (lock and KWin Wayland greeter), or Qt Virtual Keyboard in an SDDM X11 greeter selected as shown above. SDDM sends Shut down, Restart, Sleep and Hibernate through its own capability-checked API. The Classic lock has a centered **Switch User** button when Plasma allows session switching. It uses the stock private session API pinned to Plasma Workspace and KScreenLocker 6.8.2 to keep the current session locked and open the greeter. The locked-password screen has no power control, matching the Windows target. Account pictures and fonts come from KDE/SDDM. At other aspect ratios the background is cropped to cover the display; controls use logical pixels. Qt logs missing or unreadable artwork. A footer control with missing artwork is hidden rather than replaced; the password field remains usable. See `reference/tools/extract-logon-art.py` and `reference/tools/extract-logon-controls.py` for provenance.

## What Windows mode has so far

- Classic window frames (`plasma/decoration/`, a KWin QML decoration): active, inactive, maximized and pressed-button states match the reference pixel-for-pixel, including the integer caption ramp, apart from the app icon and title text. Applies to server-decorated Qt, GTK and Firefox windows; application-owned client-side titlebars remain application-owned (Firefox: enable the Title Bar customization option). Dialogs KWin recognizes as modal, including Explorer’s folder Properties and Folder Options, show only Close (plus `?` when KWin reports context help). The app/window-menu icon and KWin’s window actions, resize behavior and shortcuts are unchanged. Ordinary and nonmodal windows still use the configured caption buttons. Close-only follows the Classic decoration even when it is selected in Current mode; Current settings and non-Classic decorations are unchanged.
- Classic colors (Win32 system colors from the reference VM, as a named `Win7Classic` color scheme so nothing of a dark current theme shows through), Tahoma 8.25pt with ClearType-like RGB subpixel text (`fonts/`, limited to the installed Tahoma files), and the Win7Classic proxy style for Qt/KDE apps (complete active/inactive/disabled native palette, raster check/radio/focus primitives, native button and field variants). Shared Qt/QML rendering is documented in `classic/README.md`.
- GTK 3 apps: a Classic CSS theme (`plasma/gtk/`) on top of GTK's built-in Adwaita, switched through the `gtk-theme` GSetting so running apps restyle live. GTK 4/libadwaita apps can't be themed this way and keep their own look.
- Classic Start menu (part of the taskbar applet): favorites, All Programs (KDE's categories as folders, with a Classic scrollbar only when a list overflows), search over apps and System Settings, user folders and shortcuts on the right, Shut down and its native split-arrow session menu (capability-gated Switch user, Log off, Lock, Restart, Sleep and Hibernate). Shut down, Log off and Restart always ask through KDE's session-management dialog, even if normal KDE confirmation is disabled. Opens with Start or the Meta key. Edges, separators and highlights match `reference/screenshots/w7-menu*.png`, `w7-programs.png` and `w7-search.png` pixel-for-pixel.
- Explorer (`explorer/`, `win7-explorer`): Windows 7 Explorer's chrome at the reference's pixel geometry, drawn with Windows' own art, around KDE's KIO file widgets, so copy/paste, trash, undo, rename, Open With, properties and network locations are KDE's own. Back/Forward with history, breadcrumbs with subfolder menus, Include in library (links the folder into a library folder), Share with (properties), view menu, preview pane, help, Ctrl+W. In Windows mode it replaces Dolphin: pinned Dolphin launchers become Explorer, and folders open in it (`toggle/windows/keys/mimeapps.list`). Folder and place icons come from the `Win7-Classic` icon theme (`plasma/icons/`), which inherits Breeze for everything else. A Windows layout built before this release keeps its Dolphin pin until `win7-classic rebuild`.
- Explorer's Organize menu includes KIO Undo/Redo, current-folder or selection Properties, a working Layout menu bar and pane controls, and Folder Options. General lets you open folder items in the same Explorer window or in a new one; the address bar, navigation pane, and Back/Forward still navigate the current window. View controls hidden files and thumbnails. These Explorer-only settings update the active window, are saved to `win7-explorer-optionsrc`, and are read by new windows. Explorer filters the current listing by name; it does not provide Windows indexing or its Search options. There is no generic Remove properties operation: KIO cannot safely strip personal metadata across file formats. The command-bar View chooser keeps the genuine icons and order (distinct from the folder-background submenu). Tiles wraps 48px icons with type and file size; Content uses full-width rows with 32px icons and real dates/sizes where available. Both use KIO's live file model, selection and sort, with the existing per-folder preferences. The chooser is discrete; Windows' continuous size slider and exact popup geometry are not implemented. File metadata, type labels and file icons come from the installed KDE environment; spacing scales in logical pixels.
- Explorer's Properties for a single local folder uses the framed tabs, compact icon/name group, etched rules and button spacing of the genuine 96-DPI `reference/screenshots/w7-properties.png`. The folder art has no raised frame at rest, but the icon is still a picker with native hover, focus and pressed feedback. KDE retains its file association, size controls, timestamps, filesystem and free-space information, Permissions, Details and installed plugin pages. Windows attributes, Security and Previous Versions are not equivalents for those KDE features. There is no Apply button: KIO only exposes its complete save sequence through OK (which closes the dialog); Cancel discards pending edits. The retained fields can make the page wider; geometry scales in logical pixels rather than duplicating physical pixels at fractional scales. The native pages scroll independently of OK and Cancel. A fresh opening uses the compositor’s initial size bounds, including the panel reservation. Once mapped, stock KWin can leave part of an Explorer or Dolphin modal outside the work area when the output shrinks or a live font change grows the dialog. In testing, switching an open Classic dialog to the 17-point current profile at 800×600 and 150% extended the frame five physical pixels below the work area. Qt’s `availableGeometry` does not reflect the panel reservation on that setup, and Wayland provides no supported request to re-constrain the mapped frame. Restore the previous output size if controls are clipped; pending edits need not be discarded. Other apps, files, remote items and multi-selection keep their native Properties layout.
- Genuine Windows 7 cursors (`plasma/cursors/Win7-Classic-Cursors/`), including animated wait/working cursors, switch live in KWin and Qt/GTK apps; current mode restores its cursor theme and size. Rebuild with `python reference/tools/extract-cursors.py` (Pillow); source and the monochrome inversion limitation are documented in `reference/cursors/README.md`.
- Windows art (`explorer/assets/`, `plasma/icons/Win7-Classic/`) is extracted from the reference VM by `reference/tools/extract-assets.py`: icons from imageres/shell32/ExplorerFrame.dll, Back/Forward cropped from reference screenshots because Classic Explorer renders them differently from its bitmaps.
- Explorer Back/Forward and the Start menu's Shut down button show Classic yellow hover tips, based on `reference/screenshots/w7-explorer-back-hot.png`, `w7-explorer-forward-hot.png` and `w7-shutdown-hover.png`. The frame scales in logical pixels; the Wine Tahoma text metrics and native Windows drop shadow are not exact matches. Wayland keeps Start's popup in the work area, so its tip sits just above the button rather than over the taskbar. The Shut down tip quotes the English Windows reference; the actual action is still KDE's confirmation dialog.
- Classic taskbar (`plasma/`): Start button, Never-combine task buttons, pinned launchers, notification-area frame around the stock system tray, two-line clock and Show Desktop. Task buttons and pinned items can be dragged into any order. Edges match `reference/screenshots/w7-taskbar.png` pixel-for-pixel; icons and text differ.
- Hover a running Explorer task for its compact Classic row with the window’s icon, title and Close button. The row stays open while the pointer rests on its task or moves into it. After activating Explorer from its task button, leave the button, return, and move within it to rearm the row. Closed pins retain their yellow tips. **SUPERVISOR DISPOSITION (binding):** Escape stays with the focused app on Wayland; the applet neither grabs Escape nor steals focus. After Close, KWin reactivates the previously active window when the focused popup unmaps, while native Windows keeps shell focus. Native timing is checked on cold presentation at 100% and after a real first hover at 150%; the stock Dock renderer may delay the first 150% frame.
- The notification area uses Plasma’s stock System Tray. On first use or upgrade of a saved Classic layout, unset tray presentation options default to **Small** spacing and the direction that puts Plasma’s expander on the left in the English/LTR layout. KDE’s 26 logical px item pitch (30 at its default Normal spacing) is not Windows’ 24 px pitch, and the expander keeps Plasma’s glyph. Explicit presentation choices, nested tray settings, third-party items and current mode are preserved. The tray retains KDE’s status artwork: the icon names are shared with other controls, so changing them in the Windows-mode theme would alter those controls too.
- Click the taskbar time or date (not Show Desktop) to open the Classic calendar above the panel. Use the arrows or Page Up/Down to browse periods, click a day or use the arrow keys to browse days, and click the heading to zoom out to months, years, or decades. The footer opens KDE's Date & Time page; the applet itself never changes the clock. The calendar layout and dial come from `reference/screenshots/w7-calendar.png`; regenerate the dial with `python reference/tools/extract-calendar-dial.py`.
